## 1. 执行摘要

### 1.1 一句话判断

**LogAuditorGo 的核心价值不是"自动算出根因"，而是"把一条华为设备日志，快速、可信地连接到官方知识、现场参数和可交接的证据"。**

产品定位已经明确为**Windows 桌面单机**，这意味着：

- 不需要浏览器上传，也不需要为了"Web 通用性"增加一套上传/认证/多用户体系。
- 最佳导入方式是**后端直接读取本机路径**，并用 **Windows 原生文件/文件夹对话框**降低选择成本。
- 默认用户是一线工程师，专家能力收进工作台的"高级"抽屉。
- RCA 只作为设置页里的实验性能力保留，不进入主航道，不做后续演进。

### 1.2 五个关键结论

| # | 结论 | 证据 | 影响 |
| :-- | :-- | :-- | :-- |
| 1 | **核心价值成立，但默认路径太重** | 四级匹配、官方知识字段、参数注入、任务隔离都很完整；但导入后没有摘要，直接落入五视图专家界面 | 一线用户不知道先看什么 |
| 2 | **导入的解法不是上传，而是原生路径选择** | 当前只能填服务端绝对路径或粘贴文本；Web 路径选择器有 1,100+ 行、仍不够原生 | 桌面单机应做原生对话框，零拷贝、大文件友好 |
| 3 | **RCA 应"只保留、不演进"** | 5 条硬编码规则、约 3,300 行生产代码、6 状态调度器；无跨设备、无验证、无反馈 | 继续投入会挤占导入、知识、结论、报告 |
| 4 | **知识闭环没有合上** | 未匹配日志只显示"未匹配"，没有热点聚合、补知识入口、匹配纠错 | 产品无法越用越准 |
| 5 | **任务是"容器"，不是"案例"** | 无结论、状态、备注、工单号；历史任务无搜索/筛选/分页 | 排障结果无法沉淀，交接和复盘价值低 |

| 指标 | 数值 | 说明 |
| :-- | :-- | :-- |
| Go 生产代码 | 约 23,900 行 | 不含约 16,500 行测试代码 |

| 新建任务入口 | 3 个 | 仪表盘 / 工作台 / 历史任务，能力不一致 |

### 1.4 本版确认的 9 个产品决策

| # | 决策 | 落地方式 |
| :-- | :-- | :-- |
| 1 | **Windows 桌面单机** | 不做 LAN 多用户、不做浏览器上传、不做认证体系 |

### 1.6 90 天后的成功画面

- 新用户首次启动即看到 4 步引导；从打开产品到看到第一条"官方含义 + 可能原因 + 处理步骤"，**中位时间 < 2 分钟**。
- 导入日志时，用户点"选择文件/文件夹"弹出 Windows 原生对话框，选完直接分析；不再手填绝对路径。
- 导入完成后，用户先看到一页"这次到底发生了什么"的摘要，而不是直接面对 500 条日志。
- 每个任务都能沉淀一句可编辑的结论，并能一键复制/导出为证据包（不脱敏）。
- 知识库能看到"哪些模块没命中、哪些知识缺失、如何补"。
- RCA 默认关闭；开启后只在"高级"抽屉里出现，不自动运行、不进入主航道。

## 2. 产品定位与用户

### 2.1 产品是什么、不是什么

| 维度 | 是 | 不是 |
| :-- | :-- | :-- |
| 品类 | **Windows 桌面单机**的华为网络设备日志语义分析与故障排查工具 | 通用 SIEM / 日志集中采集平台 |
| 核心能力 | 华为 VRP/USG 日志解析、官方 HDX 知识映射、现场参数注入、证据与报告 | 实时监控与告警平台 |
| 部署 | 单二进制、离线、内网、桌面托盘、本机浏览器 | 多租户 SaaS、LAN 团队服务器 |
| 导入 | 后端直接读取本机路径；原生文件/文件夹对话框 | 浏览器拖拽上传、远端文件上传 |
| 智能 | 确定性的规则匹配、检索、模板实例化 | 不可解释的"AI 一键根因" |
| 隐私 | 数据不出本机；不做脱敏（按产品决策） | 云端分析、外部上传 |
| 用户 | 一线运维、二线专家、知识库管理员、团队负责人 | 普通消费者、非网络专业人员 |
| 边界 | 华为设备优先，单厂商深度 | 多厂商广度平台（当前阶段） |

**关键判断**：这个产品最强的地方，是把"华为官方文档"变成了"可检索、可匹配、可注入现场参数的知识"。这不是普通的日志搜索，而是**领域知识工程**。桌面单机定位进一步强化了它的优势：部署简单、数据不出机、零拷贝读取大文件。

### 2.2 目标用户与核心任务

| Persona | 典型场景 | 最想要的结果 | 当前产品满足度 | 主要障碍 |
| :-- | :-- | :-- | :-- | :-- |
| **一线值班工程师（小李）** | 收到告警，拿到一段 Syslog，需要在 10 分钟内判断严重性和下一步 | "这条日志是什么意思？我该先做什么？" | 中 | 路径选择/导入门槛、界面专家化、无摘要、无引导 |
| **二线/专家（王工）** | 多设备故障、需要还原时间线、写报告给客户/TAC | "证据链完整、可筛选、可导出、可复用" | 中高 | 多设备归属有缺陷、报告缺结论、跨任务不可检索 |
| **知识库管理员（张工）** | 导入 HDX、维护知识覆盖、处理未匹配日志 | "哪些知识缺了？怎么补？补了有没有效？" | 低 | 无覆盖分析、无自定义知识、无匹配反馈 |
| **团队负责人（刘经理）** | 看排障质量、复盘、标准化 | "这次故障怎么定位、结论是什么、能否复用？" | 低 | 任务无结论/状态、无案例库、无统计 |

**结论**：默认用户是一线工程师；专家能力必须"可发现、但不挡路"。

### 2.3 用户要完成的任务（Jobs To Be Done）

| 任务类型 | 用户原话（假设） | 产品应提供 |
| :-- | :-- | :-- |
| 功能型 | "这条日志到底什么意思？" | 解析 + 官方知识 + 现场参数 |
| 功能型 | "这次故障从哪开始？影响了什么？" | 时间线 + 关联事件 + 证据 |
| 功能型 | "我要把结论发给同事/客户/TAC" | 结论 + 报告 + 证据包 + 复制 |
| 功能型 | "上次类似问题怎么处理的？" | 案例库 + 跨任务搜索 + 知识收藏 |
| 功能型 | "哪些日志我们还没有知识？" | 未匹配热点 + 覆盖分析 + 补知识 |
| 情感型 | "我不想被一个黑盒结论误导" | 证据、证据强度、局限性、可纠错 |
| 情感型 | "我不想学一套复杂的查询语言" | 渐进披露、预设、自然语言摘要 |

### 2.4 核心价值链路

~~~mermaid
flowchart LR
    A["本机日志"] --> B["结构化解析"]
    B --> C["官方知识匹配"]
    C --> D["现场参数注入"]
    D --> E["证据与关联"]
    E --> F["结论"]
    F --> G["报告 / 交接 / 复盘"]
    C -.-> H["未匹配热点"]
    H --> I["补知识 / 自定义知识"]
    I --> C
    E -.-> J["关联事件（实验性，可选）"]
~~~

**主链路是 A→B→C→D→E→F→G；RCA 只是 E 的一个旁支。** 本版把 J 收进设置页，默认不出现。

### 2.5 "Aha Moment" 应该是什么

不是"生成了一个漂亮的 DAG 图"，而是：

> 用户点"选择日志文件"，系统弹出 Windows 原生对话框；选完立即分析。  
> 用户选中一条日志，右侧立即出现：**官方含义 + 可能原因 + 处理步骤 + 现场参数已经注入 + 匹配依据/证据强度**。  
> 用户心里想："哦，原来是这样，我知道下一步该做什么了。"

### 2.6 产品原则

1. **桌面单机优先**：不为 LAN/多用户/浏览器上传付出复杂度。
2. **零拷贝**：日志从本机路径直接读取，不经过浏览器中转。
3. **证据优先于断言**：任何自动结论都要能展开看依据。
4. **先解决 80% 的确定性问题**：这条日志是什么、官方怎么说、下一步做什么。
5. **渐进披露**：默认一线界面；专家能力收进"高级"抽屉。
6. **可逆、可恢复**：删除、覆盖、重分析要可确认、可撤销或可恢复。
7. **离线可度量**：本地记录关键漏斗，不联网。
8. **不伪造确定性**：RCA、匹配、时间推断都要显示"这是推断/这是精确匹配"。

### 3.2 工程优势（不要重写）

1. **单二进制、纯 Go、离线**：部署成本极低，是相对于 ELK/Splunk 的天然优势。
2. **任务级 SQLite 物理隔离**：归档、删除、迁移都简单。
3. **流式导入/导出**：大文件不爆内存。
4. **异步任务 + SSE/轮询 + 后台运行 + 终止**：长任务体验的基础设施已经很好。
5. **四级匹配 + 版本分档 + 互斥产品族**：这是领域护城河。
6. **参数抽取 + 模板实例化 + 摘要**：真正把"日志"变成"人话"。
7. **安全与防御性编程**：路径守卫、Zip Slip、解压炸弹、5xx 脱敏、RequestID。
8. **设计令牌与样式规范**：视觉一致性有基础。

## 4. 用户体验诊断

### 4.1 端到端旅程摩擦地图

| :-- | :-- | :-- | :-- | :-- |
| **准备知识库** | 让产品认识我关心的设备/版本 | 进入"产品文档管理"，选择服务端文件夹，扫描，导入 | 必须知道绝对路径；Web 路径选择器不够原生；无覆盖预览；无"从哪里下载 HDX"的提示 | 原生文件夹对话框 + HDX 获取指引 + 覆盖预览 |

| **初筛** | 快速找到值得看的日志 | 左栏日志卡片 + 基础筛选；注释行也混在列表里；严重度只显示 Lv.N | 没有严重度分布/时间直方图；没有"只看异常"；没有事件聚合 | 增加摘要条、时间刷选、隐藏注释、同事件聚合 |

### 4.2 页面级体验审计

#### 4.2.1 仪表盘（Dashboard）

**现状**

- 4 个累计指标卡：知识条目、文档、任务、日志总量。
- 一个"知识库各模块 Top10"柱状图。
- 右侧"快速开始"三个入口：新建任务、导入 HDX、检索知识库。

**问题**

1. **指标是"虚荣指标"**：累计任务数、累计日志量不指导今天的行动。
2. **空数据图表体验差**：无知识时图表区域几乎全空，只显示一个很小的 "No data"。
3. **没有"最近任务"**：用户回到首页看不到昨天做到哪、哪个任务失败了。
4. **没有使用说明**：新用户不知道"先导入 HDX，再建任务，再导入日志，再分析"。
5. **没有首次引导状态**：没有 checklist，也没有"继续上次引导"的入口。

**建议**

- 首屏改为"今日/最近"：最近 5 个任务、运行中/失败/待处理、最近导入文档、未匹配热点 Top5、知识覆盖概况。
- 增加 **"产品使用指引"卡片**：4 步（导入文档 → 创建任务 → 导入日志 → 分析），带"查看完整说明"。
- 顶部增加 **"?"帮助抽屉**，任何页面都可打开使用说明/HDX 获取指南/快捷键。
- 首次启动自动弹出 4 步引导；允许"暂时跳过"，首页保留 checklist。
- 空状态给出 3 步引导；累计指标降级为次级"知识库概览"。

**优先级**：P0（与首启引导一起做）。

#### 4.2.2 历史任务 / 案例库（Tasks）

**现状**

- 表格展示任务名、设备类型、设备数、文件数、日志数、匹配数、根因事件、状态、时间、操作。
- 操作有：查看审计、重新分析、重命名、导出报告、多设备报告、删除。

**问题**

1. **"设备类型"列已失去匹配意义**：任务级 device_type 只是展示元数据，不参与匹配；但界面仍把它放在显眼位置。
2. **状态显示英文**：COMPLETED、PROCESSING 直接透出；PROCESSING 还会被当成 danger 红色标签。
3. **操作列过载**：1920px 下仍换行，"删除"掉到第二行；危险操作与普通操作混在一起。
4. **没有搜索/筛选/分页**：GetTaskList 返回全部任务；任务多时无法快速找到。
5. **没有失败原因/重试**：FAILED 任务只显示红色标签。
6. **删除不可恢复**：直接删除任务数据库，没有归档/回收站/导出确认。
7. **"根因事件"列**：RCA 实验性默认关闭后，这一列会进一步误导。

**建议**

- 页面标题改为"历史排障案例"或"案例库"；导航"历史任务"改为"案例库"。
- 移除"设备类型"列，或改为"设备概况（型号自动汇总）"。
- 状态中文化 + 颜色语义：待导入、分析中（spinner + 进度）、已完成、部分成功、失败、已归档。
- 操作收纳：主操作"查看"，其余进"更多"下拉；删除放最后并二次确认。
- 增加搜索、状态筛选、时间范围、排序、分页。
- 增加"归档"和"导出任务包"，删除前提示备份。
- "根因事件"列改为"关联事件"或移除（默认不显示实验能力）。

**优先级**：P0（低成本、高感知）。

#### 4.2.3 工作台（Workbench）

**现状**

- 顶部：任务选择、设备数、匹配率、文件数、刷新/重新分析/补充导入/新建任务/导出。
- 导航：日志审计工作台、设备管理、多设备协同时间线、RCA 故障联动、多设备对比诊断报告。
- 三栏：左日志流 + 基础筛选；中结构化详情；右官方知识 + RCA Tab。
- 支持沉浸模式、快捷键、快速打标。

**目标形态（本版确认）**

- **Header**：任务选择 + 状态/时间/设备数；右侧 **"设备"按钮**、**"高级"按钮**、**"更多"**（重新分析/归档/删除）；保留"导入/导出"主操作。
- **三个 Tab**：日志分析 / 事件时间线 / 分析报告。
- **设备**：独立按钮打开设备抽屉，不再是一级视图。
- **高级抽屉**：
  - 专家筛选（现有高级筛选）
  - 关联事件（实验性，仅设置页开启后显示）
  - 原始字段/诊断信息
  - 批量操作（批量标签/导出选中）
- **右栏**：只保留官方知识 + 参数注入 + 相关事件/相似案例；删除 RCA Tab。
- **RCA**：默认不出现；设置页"实验室功能"开启后，才在"高级"抽屉出现入口；不自动运行、不随任务切换加载。
- **默认筛选**：关键词、级别、匹配状态、设备、时间范围；专家筛选不进默认栏。

**当前问题（需在实施中解决）**

1. 一级视图过多：5 个视图把用户分流。
2. 主操作过多：刷新、重新分析、补充导入、新建任务、导出，五个按钮同级。
3. 没有导入后摘要。
4. 未匹配时右栏空白。
5. RCA 顶部视图与右栏 Tab 重复。
6. 没有结论/备注。
7. 严重度只有 Lv.N。
8. 注释行混排。
9. 没有时间直方图/刷选。
10. 没有事件聚合。
11. 深链接缺失。
12. RCA 全量加载。

**优先级**：P0（Header/设备/高级抽屉/三 Tab/摘要）；P1（时间直方图、事件聚合、深链接）。

#### 4.2.4 知识库中心（KnowledgeCenter）

**现状**

- 关键词、模块、知识类型三个筛选条件；卡片网格；详情抽屉。
- 详情包含模板、描述、影响、原因、处理步骤、版本映射。

**问题**

1. **空结果计数错误**：知识库为空时，页面显示"检索结果（共 1 条）"和分页"共 1 条"，但实际 hits=[]。原因是 Bleve 的 match_all 把 mapping 版本哨兵文档计入 total，前端又过滤掉非数字 ID。
2. **错误态没有渲染**：代码里设置了 searchError，但模板没有使用。
3. **缺少产品/版本/严重度分面**：用户无法回答"这个知识适用于我的 S12700 V200R024 吗？"
4. **卡片网格不适合大量知识**：18 条/页、每张卡承载长文本；无法排序、对比、快速扫读。
5. **没有收藏/最近/复制**。
6. **没有"未匹配热点"入口**。
7. **没有自定义知识/纠错**。

**建议**

- 修复空结果计数：查询时排除 mapping 版本哨兵，或在 total 中剔除。
- 渲染错误态 + 重试按钮。
- 增加产品/版本/严重度/类型分面、排序、列表/卡片切换、关键词高亮。
- 增加收藏、最近浏览、复制知识摘要。
- 增加"未匹配热点"入口：按模块/助记符聚合未匹配日志，支持跳转到任务日志。
- 增加"本地知识补充/覆盖"与"匹配不准"反馈。
- 在知识库空状态放 HDX 获取指引。

**优先级**：P0（计数/错误态）；P1（分面/收藏/自定义知识）。

#### 4.2.5 产品文档管理（Documents）

**现状**

- 文档列表、搜索、导入 HDX 弹窗、扫描预览、批量删除、导入进度。

**问题**

1. **只能服务端路径**：需要用户知道 HDX 在机器上的绝对路径；Web 路径选择器不够原生。
2. **没有导入前的"覆盖预览"**：扫描只显示文档元数据，不告诉用户"导入后大概会增加多少知识、覆盖哪些产品/版本"。
3. **搜索是客户端过滤**：文档多时性能与体验受限；没有分页。
4. **删除没有影响提示**：用户不知道删除后会影响哪些知识匹配/历史任务。
5. **没有知识覆盖视图**。
6. **没有"如何获取 HDX"的提示**：用户可能不知道去华为官网下载，或不知道需要企业账号。
7. **没有"示例文档/演示模式"**。

**建议**

- 增加 **Windows 原生文件/文件夹对话框**，作为 HDX 导入主入口；现有 Web 路径选择器作为兜底/跨平台。
- 空状态/导入弹窗增加 **"如何获取 HDX 文档"** 卡片：
  1. 访问华为企业技术支持官网（support.huawei.com/enterprise），登录企业账号。
  2. 搜索设备型号/产品系列，进入"产品文档 / Hedex"下载 hdx 文件。
  3. 回到本产品，选择下载的 hdx 或解压目录。
  - CTA："我已下载，选择文件"。
- 扫描预览增加：预计知识条数、覆盖产品/版本、重复/冲突、预计耗时。
- 列表增加分页、产品/版本筛选、排序。
- 删除前展示影响面。
- 增加"知识覆盖概况"。
- 增加"示例知识包"（明确标注示例，不冒充官方文档）。

**优先级**：P0（原生对话框 + HDX 提示）；P1（预览/覆盖/删除影响）。

#### 4.2.6 系统设置（Settings）

**现状**

- 4 个日志指标卡；日志存放/清理策略；日志文件清单；立即清理。

**问题**

1. **只有日志**：没有索引健康、存储占用、备份恢复、版本信息、诊断包。
2. **与 README 不一致**：README 说"系统设置可查看索引健康状态、重建索引"，但页面没有入口；API 方法已存在但未被使用。
3. **没有数据目录概览**。
4. **没有备份/恢复**。
5. **没有单实例保护**。
6. **没有诊断包**。
7. **没有"实验室功能"分区**：RCA 实验开关无处安放。

**建议**

- 设置页分区：常规、数据与存储、知识库与索引、**实验室功能**、关于/诊断。
- **实验室功能**：唯一开关"启用关联事件（实验性）"，默认关闭；旁边写明"只保留、不演进、可能误报"。
- 增加索引健康 + 重建按钮。
- 增加存储概览与清理。
- 增加一键备份/恢复、单实例保护、诊断包、版本信息。
- 不在设置里放"高级模式"开关；高级模式由工作台"高级"按钮打开。
- 不做脱敏设置。

**优先级**：P0（索引健康/存储概览/实验室分区）；P1（备份/诊断/单实例）。

| 红路线 | 目标 | 当前结果 | 判定 |

## 5. RCA 专题评估：只保留，不演进

### 5.1 最终决策

**RCA 不再作为产品主功能，也不做任何后续演进。保留代码，作为设置页里的实验性能力；默认关闭；只在"高级"抽屉出现；不自动运行；不随任务切换加载；不进入任务 KPI 和主报告。**

这不是"技术否定"，而是**产品组合决策**：

- 作为**根因推断引擎**：它承诺了"根因"，但只覆盖 5 条预置故障链，不支持跨设备，准确率没有数据验证。**投入产出比不成立。**
- 作为**证据组织能力**：窗口聚类、实体一致性、传播链展示仍有参考价值，所以不删除代码，保留为实验功能。
- 作为**主功能/主导航/KPI**：它过度了。**必须撤出主航道。**

一句话：**保留它的"证据组织"能力，去掉它的"因果断言"包装，停止一切演进投入。**

### 5.2 当前 RCA 到底做了什么

| 维度 | 现状 | 评价 |
| :-- | :-- | :-- |
| 规则库 | 5 条硬编码规则（LINK_ROUTING、OPTICAL_CRC、RADIUS_AUTH、MLAG_PEERLINK、RESOURCE_OVERLOAD） | 规则少、维护需改代码、无规则管理 |
| 匹配方式 | 模块精确 + 助记符关键词包含；实体参数（接口/对端 IP/会话 ID）做一致性校验 | 工程细致，但仍是启发式 |
| 算法 | 300s 重叠窗口（60s 重叠）+ 倒排 BFS + 排他认领 + 多因子证据强度 | 算法底座合格，保留为"关联" |
| 触发 | 导入/重分析时自动全量运行；异步调度器，默认并发 2 | 用户未要求也运行，资源与认知成本高 |
| 分析范围 | 严格按 DeviceID/Hostname 隔离 | 与多设备协同割裂，最重要的跨设备场景缺失 |
| 证据强度 | 深度/条数/时间衰减/实体一致性加权 | 未利用匹配置信度、知识严重度等外部信号 |
| 结果 | RCAEvent 持久化，RcaCenter/RcaGraph 可视化 | 只读展示，无确认/否决/反馈 |
| 建议动作 | 每条规则硬编码 ActionTemplate | **不是官方文档原文**，却以"官方推荐"口吻展示 |
| 状态机 | PENDING/QUEUED/RUNNING/COMPLETED/TIMEOUT/FAILED | 6 个状态、超时、并发、重启自愈，运营复杂 |
| 规模上限 | 10 万行样本、2,000 事件/次、500 衍生/事件、300s 超时 | 多个硬上限，说明大任务下并不"完整" |

### 5.3 成本分析：代码、认知、运营、机会

#### 5.3.1 代码成本

| 模块 | 规模 | 说明 |
| :-- | :-- | :-- |
| internal/rootcause | 约 1,169 行 | engine 917 + cluster 111 + topology 141 |
| internal/task/rca_scheduler.go | 约 580 行 | 异步调度、状态机、重启自愈 |
| internal/model/rca.go | 约 57 行 | 数据模型 |
| API/Service 相关 | 约 250~400 行 | 查询、富化、重算、导出集成 |
| 前端 RcaCenter | 约 900 行 | KPI、列表、详情、三种 Tab、状态处理 |
| 前端 RcaGraph | 约 140~160 行 | ECharts DAG |
| 其他前端 | 约 100~200 行 | 轮询、store 索引、日志详情/知识面板的 RCA 入口 |
| 测试 | 约 650 行 rootcause + task 层 RCA 回归 | 质量投入高 |
| **合计** | **约 3,300 行生产代码 + 近 1,000 行测试/文档** | 约占全部生产代码 7.8% |

**关键不是行数，而是"每行代码承载的业务规则只有 5 条"**。这是一个典型的高固定成本、低边际收益结构。

#### 5.3.2 认知成本

用户在 RCA 界面需要同时理解：

- 什么是疑似根因、衍生、影响等级；
- 什么是证据强度、传播深度、时间衰减；
- 什么是 DAG、边、延迟；
- 为什么这条链是根因、那条不是；
- TIMEOUT/QUEUED/RUNNING 分别意味着什么；
- 证据强度 80% 到底代表什么。

对一线工程师，这些概念没有直接对应的操作动作；对二线专家，这些信息又不足以支撑严谨结论。**结果是两头不讨好**。

#### 5.3.3 运营成本

- 每条新规则要改 Go 代码、补测试、重新构建、发版；
- 规则命中率、误报率没有统计；
- 用户无法确认/否决/改判；
- 跨设备场景需要额外拓扑模型，成本更高；
- 大任务超时/截断需要解释；重启自愈需要测试；
- 每个任务都自动运行，CPU/IO 与用户浏览争抢资源；
- 每次切换任务都全量拉取 RCA 事件，前端性能受影响。

#### 5.3.4 机会成本

根据 RCA演进计划.md，后续还要投入：

- 方案 A 规则平台化：后端 2~3 周 + 前端 1 周；
- 方案 B 跨设备 RCA + 信号融合 + 增量：4~6 周；
- 方案 C 统计学习 + 反馈闭环：长期、依赖数据积累。

合计 **7~9 周以上**，而且方案 B/C 的风险和不确定性更高。本版决策：**这 7~9 周不投入 RCA，全部转投导入、摘要、知识闭环、报告。**

### 5.4 准确性与信任风险

| 风险 | 说明 | 后果 |
| :-- | :-- | :-- |
| **规则覆盖长尾不足** | 真实网络故障成百上千，5 条规则只是骨架 | 大量真实根因识别不到，用户逐渐不信任 |
| **跨设备缺失** | 真实故障常是"上联口 Down → 整排接入邻居翻滚"，当前按设备隔离 | 最有价值的场景无法覆盖 |
| **实例校验仍有限** | 只校验接口/对端 IP/会话 ID 等参数；参数缺失时退化为模块+时间 | 同设备不相关事件可能被串成链 |
| **建议动作不官方** | ActionTemplate 是硬编码文案，不是知识库原文 | 以"官方推荐"展示会误导用户 |
| **证据强度口径不透明** | 用户不知道 0.8 是怎么来的；代码里还有 confidence 为 0 时前端显示 80% 的问题 | 低置信度被误读为高置信度 |
| **影响等级与证据强度脱节** | impactLevelOf 只看衍生条数与根因严重度，不看证据强度 | 低证据强度也可能标 CRITICAL |
| **无反馈闭环** | 用户不能确认/否决/改判 | 误报无法收敛 |
| **无验证数据集** | 没有真实事故标注与 precision/recall | 无法证明"准确率"，只能靠演示 |
| **自动运行造成"已分析"错觉** | 任务完成即显示 RCA COMPLETED，即使 0 事件 | 用户以为"系统看过了，没问题" |

**即使只保留，也应修两个显示缺陷：**

1. RcaCenter 使用 confidence 默认 0.8 的写法，置信度为 0 或缺失时显示 80%；应显示"证据不足"而不是 80%。
2. 级别筛选只提供 ALL/CRITICAL/HIGH/MEDIUM，但后端会产出 LOW；LOW 事件在筛选器里不可见。

### 5.5 保留方式（设置页实验开关）

| 项目 | 决策 |
| :-- | :-- |
| 默认状态 | **关闭** |
| 开关位置 | **设置页 → 实验室功能 → 启用关联事件（实验性）** |
| 开启后入口 | **只在工作台"高级"抽屉**，不进入主导航、不进入右栏 Tab |
| 运行方式 | **用户手动点击"分析关联事件"**；导入/重分析不自动触发 |
| 加载方式 | 按需加载，分页；任务切换不拉取 RCA |
| 任务列表 | 不显示"根因事件"列；最多显示"关联事件"且默认隐藏 |
| 报告 | 不进入主报告；最多作为可选折叠章节 |
| 命名 | "关联事件（实验性）"；"疑似根因/关联起点"；"证据强度" |
| 后续演进 | **不做** A/B/C、跨设备、规则平台、统计学习、反馈闭环 |
| 代码处理 | 保留；只修 confidence/LOW 两个显示 bug；不重构 |
| 用户提示 | 顶部说明规则范围、样本上限、可能误报、非官方建议 |

### 5.6 明确不做的事

- 不做规则平台化（方案 A）。
- 不做跨设备拓扑 RCA（方案 B）。
- 不做统计学习/反馈闭环（方案 C）。
- 不做 4 周验证/扩张计划。
- 不做规则管理 UI、规则命中率看板、用户确认/否决闭环。
- 不把 RCA 作为演示主卖点。
- 不把 RCA 数量作为任务 KPI。

### 5.7 如何向利益相关方沟通

- **不要说"RCA 没用"**，要说"RCA 目前是实验性能力，证据不足以支撑主功能定位；我们保留代码，把它放到设置页实验开关和高级抽屉，停止后续投入"。
- **不要直接删除代码**，保留一个版本周期的回滚能力；只修显示 bug。
- **用机会成本说话**：省下的 7~9 周投入导入、摘要、知识闭环、报告。
- **给演示留出口**：设置里可开启，高级抽屉仍可展示 DAG；但默认界面不再用它做主卖点。
- **把"不做什么"写进路线图**，让团队看到资源转向。

## 6. 功能优化组合：增加、优化、移除

### 6.1 优先级方法

- **P0（必须做）**：不做会阻塞核心任务或造成明显信任损失；0~4 周内可交付。
- **P1（应该做）**：显著提升效率/留存，但可在一个季度内排期。
- **P2（以后做）**：战略选项，需先验证需求或依赖前置能力。
- **投入图例**：S ≤ 1 周；M = 1~3 周；L = 3~6 周；XL > 6 周（按 2 人团队估算）。

### 6.2 P0：先把主链路打通

#### F1. 原生文件/文件夹对话框 + 统一导入向导（不做浏览器上传）

**问题**：当前只能填绝对路径或粘贴；Web 路径选择器可用但不够原生；新建任务有三个入口，能力不一致。

**方案**

- 新增 Windows 原生文件/文件夹对话框：
  - "选择文件"：多选 log/txt/syslog/gz；支持最近目录。
  - "选择文件夹"：递归收集日志；显示预计文件数与大小。
  - 后端返回绝对路径给前端；后端直接读取，不经浏览器上传。
  - 非 Windows/原生对话框不可用时，回退到现有 Web 路径选择器。
  - 保留"粘贴路径"作为高级/排障入口。
- 统一"新建排障"向导：
  1. 任务信息：名称、备注（设备类型自动/可跳过）。
  2. 日志来源：原生文件/文件夹 / 粘贴文本 / 最近路径。
  3. 导入预览：文件列表、大小、检测到的 Hostname/设备、时间范围、同名冲突、预计耗时。
  4. 开始分析 → 进度 → 诊断摘要。
- 统一仪表盘、工作台、案例库的入口，全部指向同一向导。
- **不做**浏览器拖拽上传、不做 multipart 上传、不做远端上传。

**验收**

- 点击"选择文件/文件夹"弹出 Windows 原生对话框；选完返回路径并进入预览。
- 10 万行日志从选择到开始分析 ≤ 3 次点击。
- 非 Windows 或原生对话框失败时自动回退到 Web 路径选择器。
- 三个入口行为一致；同名冲突有明确选择。
- 不产生浏览器上传临时文件。

**投入**：M（1.5~2.5 周；原生对话框 3~5 天 + 向导/预览 1~2 周）。

**依赖**：现有导入流水线、进度中心、fsx 路径守卫。

**风险**：Windows 对话框线程/COM 初始化；路径编码（UTF-16）；大目录扫描耗时；非 Windows 回退。

#### F2. 导入后"诊断摘要"

**问题**：导入完成即进入三栏工作台，用户不知道先看什么；RCA 还会在后台跑。

**方案**

- 新增"分析摘要"页/抽屉，作为导入完成后的默认落地页：
  - **概览**：任务名、时间范围、设备数、日志数、解析成功率、知识覆盖率、严重度分布。
  - **最值得看**：Top 5 高严重度/高频模块，带样例日志与知识匹配状态。
  - **知识盲区**：未匹配 Top 10 模块/助记符，带"去知识库/补知识/查看日志"。
  - **关联事件**：事件簇/时间线摘要（不称根因；默认不展示 RCA）。
  - **下一步建议**：3 条可执行动作。
- 支持"开始逐条排查"进入工作台，自动选中第一条高严重度日志。
- 摘要可导出/复制为 Markdown。

**验收**

- 导入完成后 100% 进入摘要；摘要数据与任务库一致。
- 从摘要到第一条日志的点击 ≤ 2 次。
- 摘要首屏加载 < 1 秒（10 万行任务，预聚合）。

**投入**：M（1~2 周；后端聚合 SQL + 前端页面）。

#### F3. 匹配质量与知识盲区分析

**问题**：匹配率只有一个百分比；用户不知道 EXACT/TEMPLATE/BLEVE 各占多少，也不知道哪些模块最缺知识。

**方案**

- 匹配质量分布：EXACT / MNEMONIC / TEMPLATE / BLEVE / FAMILY_SUSPECT / UNMATCHED。
- "未匹配热点"：按 module + brief 聚合，展示次数、设备、样例、首次/最后时间；支持跳转日志、复制清单、导出 CSV。
- "知识覆盖"：按产品/版本/模块统计知识条目与命中次数；显示"有知识但从未命中"的条目。
- 日志详情显示"匹配依据"：命中层级、命中字段、候选数量、版本映射。
- "匹配不准"反馈：记录 log_id、knowledge_id、反馈类型，本地落库。

**验收**

- 摘要页可看到 6 类匹配分布；未匹配 Top 10 可跳转过滤后的日志。
- 日志详情可展开"匹配依据"。
- 反馈可在本地查看/导出，不上传。

**投入**：M（1~2 周）。

#### F4. 任务升级为"案例"：结论、状态、备注

**问题**：任务只是容器；没有结论、状态、备注、工单号；无法交接与复盘。

**方案**

- TaskInfo 增加：case_status（排查中/已定位/已解决/已归档）、conclusion、notes、external_ref、任务标签。
- 工作台顶部增加"结论"按钮，打开侧边抽屉：
  - 自动生成结论草稿（基于统计、Top 事件、知识命中、未匹配）；
  - 用户可编辑、保存；
  - 支持插入证据链接。
- 案例库增加状态、结论摘要、搜索/筛选/排序。
- 报告自动带入结论。

**验收**

- 任意任务可保存/编辑结论；刷新后不丢失。
- 案例库可按状态/关键词/标签筛选。
- 报告包含结论章节。

**投入**：M（1~2 周）。

#### F5. 证据报告与一键复制（不做脱敏）

**问题**：现有 HTML 报告只有指标、RCA 摘要、日志表；没有结论、证据链、可复制摘要。

**方案**

- 报告结构升级：
  - 执行摘要（结论 + 3~5 条关键发现）；
  - 关键证据（Top 事件 + 原始日志 + 知识引用 + 时间线）；
  - 关联事件（事实描述；不含 RCA 主链）；
  - 未匹配/待补充；
  - 处置建议（引用知识条目，标注来源）；
  - 方法与局限。
- 增加"复制摘要"（Markdown/纯文本）。
- 文件名改为"任务名_日期.html"。
- 增加打印样式，支持浏览器另存 PDF。
- 证据包 zip：HTML + CSV + JSON 元数据 + 选中日志 + 知识引用。
- **不做脱敏**；证据包保留原始内容，由用户自行决定是否外发。

**验收**

- 报告打开即可看到结论与 3 条关键证据。
- 复制摘要包含任务、时间、设备、关键事件、知识建议、局限。
- 文件名可读；打印无布局错乱。
- 证据包可解压、可离线打开。

**投入**：M（1~2 周；模板 + 聚合）。

#### F6. 知识库索引健康与存储概览

**问题**：API 已有索引状态/重建，但前端没有入口；设置页只有日志。

**方案**

- 设置页增加"知识库与索引"卡片：索引文档数 vs 知识数、mapping 版本、最后重建时间、是否漂移；"重建索引"按钮。
- 增加"数据与存储"卡片：知识库、Bleve、任务库、日志占用；清理临时文件/过期日志。
- README 同步更新。

**验收**

- 索引漂移可见；重建可一键完成并有进度。
- 存储占用与实际文件一致。
- 文档与 UI 一致。

**投入**：S~M（3~5 天）。

#### F7. 任务列表与仪表盘快修

**问题**：任务列表无搜索/筛选/分页；状态英文；操作列换行；仪表盘虚荣指标。

**方案**

- 任务列表：搜索、状态筛选、时间范围、排序、分页；状态中文化；操作收纳；失败原因 tooltip；归档/导出任务包。
- 仪表盘：最近任务、待处理、未匹配热点、最近文档、首次使用 checklist；累计指标降级。
- 修复知识库空结果 total=1；修复 searchError 渲染；修复 PROCESSING 状态颜色。

**验收**

- 100 个任务下列表可用；搜索/筛选响应 < 300ms。
- 状态全部中文；PROCESSING 显示 spinner；FAILED 有原因。
- 空知识库不再显示"共 1 条"。

**投入**：S（1 周）。

#### F8. 工作台 IA 收敛：设备按钮 + 高级抽屉 + 三 Tab

**问题**：5 个一级视图、5 个主操作、RCA 重复、设备管理占一级视图。

**方案**

- Header：任务选择 + 状态/时间/设备数；右侧"设备"按钮、"高级"按钮、"更多"（重新分析/归档/删除）；保留导入/导出主操作。
- 一级 Tab 收敛为：日志分析 / 事件时间线 / 分析报告。
- 设备管理改为抽屉，不再是一级视图。
- 高级抽屉：专家筛选、关联事件（实验开启时）、原始字段/诊断、批量操作。
- 删除右栏 RCA Tab；RCA 只在高级抽屉。
- 默认筛选只保留高频项；专家筛选进高级抽屉。

**验收**

- 默认界面一眼可完成"选任务 → 看日志 → 看知识"。
- 设备按钮 1 次点击打开设备抽屉。
- 高级抽屉可打开专家筛选；RCA 默认不可见。
- 3 个一级 Tab 覆盖 90% 使用场景。

**投入**：M（1~2 周；前端为主）。

#### F9. 首启 4 步引导 + 首页使用指引 + HDX 获取提示

**问题**：新用户没有 HDX 时看不到核心价值；不知道先做什么；不知道 HDX 去哪下载。

**方案**

- 首次启动自动弹出 4 步引导：
  1. 导入 HDX 文档（含"去华为官网下载"提示；可暂时跳过，提示未导入知识时匹配率为 0）。
  2. 创建排障任务（名称/备注）。
  3. 导入日志（原生文件/文件夹对话框；支持多选/递归）。
  4. 开始分析 → 查看诊断摘要/知识匹配。
- 允许"暂时跳过"；首页保留 checklist，直到 4 步完成。
- 引导状态存后端数据目录（而非 localStorage），避免清缓存反复触发。
- 首页增加"产品使用指引"卡片；顶栏"?"帮助抽屉。
- 文档页/HDX 导入弹窗增加"如何获取 HDX"卡片，链接华为企业支持官网。

**验收**

- 首次启动必现引导；可跳过；首页 checklist 可继续。
- 新用户 10 分钟内完成首次任务并看到知识匹配（有 HDX 或示例数据）。
- HDX 提示含官网链接、搜索型号、下载 hdx 三步。
- 清浏览器缓存不会重复触发。

**投入**：M（1~1.5 周；内容制作是主要成本）。

### 6.3 P1：让产品越用越准、越用越省

#### F10. 自定义知识与匹配覆盖（Knowledge Override）

**问题**：官方 HDX 不可能覆盖所有现场场景；未匹配日志没有补知识入口；匹配错误无法纠正。

**方案**

- 本地知识条目：module、brief、产品族/型号/版本、含义、原因、处理步骤、参考链接、严重度。
- 匹配覆盖：把某个 module/brief 绑定到已有官方知识或自定义知识。
- 优先级：本地覆盖 > 官方精确 > 助记符 > 模板 > Bleve。
- 置信度标记：LOCAL_EXACT（0.95）/ LOCAL_MAPPING（0.9），UI 显示"本地知识"。
- 入口：未匹配日志详情 → "补充本地知识/绑定到已有知识"；知识库中心 → "新建知识"；CSV/Markdown 导入。
- 管理：列表、搜索、启用/禁用、删除、导出。

**验收**

- 用户可在 1 分钟内把一条未匹配日志绑定到已有知识，并立即生效。
- 本地知识在日志详情/报告中显示来源。
- 支持导入/导出 CSV；冲突有提示。

**投入**：M~L（2~3 周）。

#### F11. 跨任务案例库

**问题**：历史任务无搜索/筛选/分页；无法回答"上次类似问题怎么处理"。

**方案**

- "案例库"视图：任务名、时间、设备、状态、结论摘要、标签、工单号、关键事件。
- 搜索：任务名、结论、标签、module/brief、设备 Hostname、日期范围。
- 先做元数据/结论检索，不做全量原始日志全局索引。
- 支持"另存为模板"和"复制案例链接"。

**验收**

- 输入 "BGP" 能找回相关任务。
- 搜索响应 < 500ms（1000 任务以内）。
- 可从案例一键打开工作台并恢复筛选。

**投入**：M（2 周）。

#### F12. 备份/恢复、诊断包、单实例

**问题**：任务库是物理 SQLite；误删/换机/升级有风险；无双开保护；无诊断包。

**方案**

- 一键备份：zip 打包 knowledge.db、bleve、tasks、config；保留最近 3 份。
- 恢复：校验版本与完整性；恢复前自动备份。
- 诊断包：配置 + 最近日志 + DB 状态 + 索引状态 + 版本。
- 单实例：Windows named mutex / lock file；第二次启动打开已有浏览器地址或提示。

**验收**

- 备份/恢复在 1GB 数据下可用。
- 双开不会启动第二个服务。
- 诊断包不含明文密钥。

**投入**：M（1~1.5 周）。

#### F13. 日志浏览效率：聚合、直方图、隐藏注释

**问题**：500 张卡片、注释噪声、无时间概览、重复事件多。

**方案**

- 默认隐藏 COMMENT 行，显示"显示注释（N）"开关。
- 严重度堆叠时间直方图，支持刷选。
- "聚合视图"：同一 module/brief/实体在时间窗口内聚合为一行。
- "只看异常"。
- 虚拟滚动/分页优化。
- 语义严重度标签（严重/错误/警告/提示 + Lv.N）。

**验收**

- 10 万行任务首屏 < 1.5 秒。
- 聚合视图减少 80% 重复卡片。
- 时间刷选后列表/计数同步。

**投入**：M~L（2~3 周）。

#### F14. 修复单文件多设备归属

**问题**：实测 10 条日志含 2 个 Hostname，全部归属到第一台设备；另一台 0 条；重分析不修。

**方案**

- 导入时按行解析 Hostname，逐行写入正确 device_id；或检测到多 Hostname 时不预分配，交给 AutoAssign。
- 增加 device_assignment_source（auto/manual）；自动归属只改 auto。
- 导入预览显示检测到的设备列表与行数分布。
- 对存量任务提供"重新归属（预览）"工具。

**验收**

- 示例文件导入后两台设备日志数正确。
- 手工归属不被自动覆盖。
- 存量任务可预览后修复。

**投入**：M（1~2 周）。

### 6.4 P2：战略选项，先验证再投入

| 功能 | 价值 | 成本/风险 | 建议 |
| :-- | :-- | :-- | :-- |
| **实时 Syslog 接收（UDP/TCP 514）** | 从"事后分析"变"实时排障" | 端口/防火墙/存储增长/安全；3~4 周 | 先访谈 5 个用户；桌面单机不是刚需前不做 |
| **本地 LLM/RAG 助手** | 自然语言总结、处置建议 | 模型分发/内存/离线部署/幻觉/评测；4~8 周 | 先做检索与自定义知识；LLM 只做"引用式助手" |
| **多厂商（H3C/Cisco/Juniper）** | 扩大市场 | 解析器 + 知识模型 + 文档源；6~12 周 | 先把华为做到极致 |
| **深色模式** | NOC 夜间使用 | 前端适配；2~3 周 | 可做；令牌化基础好 |
| **移动端/多人协作/LAN 团队模式** | — | 与桌面单机定位冲突 | **不做** |

### 6.7 Feature Flag 与清理策略

建议在配置中增加：

~~~yaml
features:
  rca: false                  # 设置页实验室功能，默认关闭
  native_file_dialog: true    # Windows 原生文件/文件夹对话框
  browser_upload: false       # 明确关闭，不做
  lan_mode: false             # 明确关闭，不做
  masking: false              # 明确关闭，不做
~~~

原则：

- 新功能默认关闭或灰度，避免影响主链路。
- RCA 先隐藏、后清理；保留一个版本周期的回滚。
- 删除代码前，先确认无数据依赖、无用户配置、无外部 API 调用。
- 每个 feature flag 有负责人、过期时间、清理 issue。

## 8. 路线图与优先级

### 8.1 排期原则

1. **先止血，再增强**：先修误导性 UI、RCA 主航道、空状态/错误态，再做大功能。
2. **先主链路，再专家能力**：原生导入 → 摘要 → 知识 → 结论 → 报告，优先于高级筛选。
3. **每个阶段都有可验证的用户结果**：不是"做完了功能"，而是"用户能更快得到结论"。
4. **能删就删，能藏就藏**：不为低使用率功能维护两套路径。
5. **先做可逆的**：UI 调整、feature flag、文案、状态映射可以先上；数据模型变更要配迁移与备份。

### 8.2 阶段总览

| 阶段 | 时间 | 主题 | 关键交付 | 成功标志 |
| :-- | :-- | :-- | :-- | :-- |
| **Phase 0** | 第 1~2 周 | 止血与降噪 | 命名/状态/操作列；RCA 设置页实验开关 + 高级抽屉；设备按钮；三 Tab；知识库空结果/错误态；索引健康；前端冒烟 | 主界面无 RCA 一级入口；设备/高级按钮可用；4 条红路线有自动化测试 |
| **Phase 1** | 第 3~6 周 | 主链路打通 | Windows 原生文件/文件夹对话框；统一导入向导；导入预览；诊断摘要；匹配质量；案例结论；报告/证据包 | 新用户 10 分钟内看到第一条有效知识；导入完成即看到摘要 |

### 8.6 Definition of Done

1. 验收标准明确，产品/研发/测试三方确认。
2. Go 单测 + 前端 E2E（红路线）通过；关键逻辑有回归测试。
3. 空态/错误态/加载态可用；有重试或下一步。
4. 键盘可操作；严重度/状态不只靠颜色。
5. 性能预算达标（首屏、查询、导入）。
6. 文档/README/发布说明同步。
7. 本地使用事件埋点（opt-in）覆盖关键漏斗。
8. 无新增 P0/P1 缺陷；无数据丢失风险。

### 8.7 本年度明确不做

- 不做浏览器上传、LAN 多用户/认证、脱敏。
- 不做 RCA 的任何演进（A/B/C、跨设备、规则平台、统计学习、反馈闭环）。
- 不做实时 Syslog 接收（除非用户访谈证明刚需）。
- 不做本地 LLM/RAG（先做检索与自定义知识）。
- 不做多厂商（先把华为单机做深）。
- 不做移动端/多人协作。
- 不重写后端引擎；在现有模块上做增量。

## 9. 指标体系：如何证明我们做对了

### 9.1 北极星指标

**Time to First Insight（TTFI）**：从导入完成到用户看到第一条"有效知识/结论"的中位时间。

- "有效"定义：知识匹配成功且用户展开/停留 ≥ 3 秒，或用户保存了结论/标记。
- 目标：**< 2 分钟**（有知识库）；**< 5 分钟**（无知识库，走示例/补知识）。
- 辅助北极星：**每周完成的案例数**（保存结论或导出报告的任务数）。

### 9.2 漏斗指标

| 阶段 | 事件 | 目标 |
| :-- | :-- | :-- |
| 打开 | app_open | 基线 |
| 首启引导完成/跳过 | onboarding_complete / skip | 完成率 ≥ 60%，跳过率 ≤ 40% |
| 开始导入 | import_start | ≥ 80% 新用户 |
| 原生对话框使用 | native_dialog_open / confirm | 成功返回路径 ≥ 95% |
| 导入完成 | import_complete | ≥ 90% 开始导入的用户 |
| 查看摘要 | summary_view | ≥ 80% 导入完成 |
| 选中日志 | log_select | ≥ 70% 摘要查看 |
| 查看知识 | knowledge_view | ≥ 60% 选中日志 |
| 保存结论 | conclusion_save | ≥ 40% 完成任务 |
| 导出报告/证据包 | export | ≥ 30% 完成任务 |
| 高级抽屉 | advanced_open | 基线，观察使用率 |
| 7 日回访 | return_7d | ≥ 30%（桌面工具可更低，先建基线） |

### 9.3 质量指标

| 指标 | 定义 | 目标 |
| :-- | :-- | :-- |
| 解析成功率 | 成功解析行 / 非空非注释行 | ≥ 99%（支持格式） |
| 知识覆盖率 | 匹配行 / 非注释行 | 基线 + 10pp（3 个月） |
| 精确匹配占比 | EXACT / 匹配行 | 基线 + 5pp |
| 未匹配热点下降 | Top 未匹配模块次数 | 补知识后下降 ≥ 20% |
| 匹配纠错率 | 用户标记"不准"/匹配行 | ≤ 5% |
| 原生对话框成功率 | 打开后成功返回路径 / 打开次数 | ≥ 95% |
| 报告完整率 | 含结论+证据+建议的报告 / 导出报告 | ≥ 90% |
| 错误率 | 5xx / 请求 | < 0.5% |
| 崩溃/卡死 | 会话 | < 0.5% |

### 9.5 本地埋点方案（离线、隐私优先）

- 新增本地表 usage_events：event、task_id（可空）、timestamp、props_json、app_version、duration_ms。
- 默认开启"匿名本地统计"，不联网；设置页可关闭/清空/导出。
- 不记录原始日志、IP、主机名、知识内容；只记录计数、功能 ID、路径类型（原生/Web/粘贴）。
- 事件示例：
  - onboarding_start / onboarding_complete / onboarding_skip
  - native_dialog_open / native_dialog_confirm / native_dialog_cancel
  - import_start（source=native_file/native_folder/paste_path/paste_text）
  - import_complete（lines, files, devices, duration）
  - summary_view（matched_rate, unmatched_top_n）
  - log_select（severity, matched）
  - knowledge_view（tier）
  - conclusion_save（length）
  - export（format, evidence_package）
  - advanced_open（tab）
  - error（code, feature）
- 保留 90 天；设置页"导出使用报告"生成 CSV。
- 这样既能度量，又不破坏"100% 离线"的承诺。

### 9.6 复盘节奏

- 每 2 周：看漏斗与性能，调整优先级。
- 每月：看知识覆盖率、未匹配热点、原生对话框成功率、首启完成率。
- 每季度：用户访谈 + SUS + 路线图重排。
- RCA：只做"默认关闭/无自动运行/不加载"的冒烟检查，不做演进评估。

## 10. 验证计划：别用"我觉得"做产品

### 10.1 用户研究

- 访谈 5~8 名目标用户：一线运维 3、二线专家 2、知识库管理员 1~2、负责人 1。
- 采用情境访谈：让他们拿一份真实日志，现场完成"选择文件 → 分析 → 找到答案 → 写结论 → 导出"。
- 记录：卡点、原话、绕路方案、时间、情绪。
- 重点验证：
  - 他们是否接受 Windows 原生文件/文件夹对话框？是否还需要 Web 路径选择器？
  - 他们是否有 HDX 文档？从哪里下载？是否有企业账号/内部镜像？
  - 他们是否需要首启引导？希望跳过还是强制完成？
  - 他们如何写结论/交接？现有报告缺什么？
  - 他们是否会打开"高级"抽屉？专家筛选是否可发现？

### 10.2 语料审计

- 收集 20 个真实故障案例（脱敏），覆盖 BGP/OSPF/IFNET/AAA/WLAN/防火墙。
- 标注：已知根因、关键事件、时间范围、设备。
- 测量：
  - 解析成功率；
  - 知识覆盖率/精确匹配率；
  - 未匹配 Top；
  - 报告是否能支持人工复盘。
- **RCA 不纳入本轮评估**：按决策只保留、不演进；只做"默认关闭/不自动运行/不加载"的冒烟检查。

### 10.3 可用性测试

- 5 名用户，4 个任务：
  1. 首次启动，完成/跳过 4 步引导，并从首页 checklist 继续。
  2. 用原生文件对话框导入一份日志，找到一条严重告警的官方解释。
  3. 把一条未匹配日志补充为本地知识。
  4. 写结论并导出报告/证据包（不脱敏）。
- 指标：成功率、时间、错误数、SUS、主观信任。
- 观察：是否使用"设备"/"高级"按钮；是否理解"关联事件（实验性）"；是否找到导出。

### 10.4 RCA 实验功能冒烟测试（不演进）

| 检查项 | 期望 |
| :-- | :-- |
| 默认状态 | 设置页实验室开关关闭；主界面无 RCA 入口 |
| 关闭时 | 无主导航、无右栏 Tab、无任务 KPI；导入/重分析不自动跑；任务切换不加载 |
| 开启时 | 只在"高级"抽屉出现"关联事件（实验性）"；用户手动点击才分析 |
| 显示 | confidence 为 0 不显示 80%；LOW 可筛选；有免责声明 |
| 代码 | 保留，不重构、不扩规则、不做 A/B/C |

### 10.5 决策记录（已确认）

| 决策 | 结论 | 依据 | 后续 |
| :-- | :-- | :-- | :-- |
| 部署模式 | Windows 桌面单机 | 零拷贝、离线、低复杂度 | 不做 LAN/浏览器上传/认证 |
| 导入方式 | 原生文件/文件夹对话框 + Web 路径选择器兜底 | 桌面单机最佳体验 | 第一期实施 |

| HDX 提示 | 华为官网 + 首页卡片 + "?"帮助抽屉 | 用户普遍有 HDX | 文案/内容制作 |
| 脱敏 | 不做 | 产品决策 | 证据包保留原始内容 |
| 命名 | 按术语表改 UI | 降低认知成本 | 与功能实施同步 |

## 12. 结论与建议

### 12.1 战略选择

**把确定性做深，把不确定性做轻；把桌面单机做透，把 Web 通用性放下。**

- **做深**：原生路径选择、解析、官方知识匹配、参数注入、证据、结论、报告、案例复用。
- **做轻**：RCA、LAN、浏览器上传、脱敏、多厂商、LLM 根因。这些不作为当前产品的主航道。

### 12.2 三个赌注

1. **导入体验是增长杠杆**：桌面单机 + 原生对话框 + 零拷贝，是相对 Web 工具的真实优势。
2. **知识闭环是留存杠杆**：用户补的知识越多，产品越懂现场，迁移成本越高。
3. **结论/报告是传播杠杆**：一份可交接的证据包，会把产品带进团队/客户/TAC 的工作流。

### 12.3 对 RCA 的最终建议

- **不在主界面保留"根因"承诺**；改为"关联事件（实验性）"。
- **不继续 A/B/C 扩张**；把 7~9 周投入到 P0/P1。
- **保留代码，但默认关闭**；设置页实验开关 + 高级抽屉；只修 confidence/LOW 显示 bug。
- **不自动运行、不全量加载、不进入任务 KPI/主报告**。
- **不做验证/扩张计划**；未来若重启，另立项目。

### 12.4 90 天期望结果

| 结果 | 基线（推断） | 90 天目标 |
| :-- | :-- | :-- |
| 首次导入成功率 | 未知，受路径限制 | ≥ 80% |
| 原生对话框成功率 | 0（未实现） | ≥ 95% |
| 首次看到知识的时间 | 未知，可能 > 10 分钟 | < 2 分钟 |
| 首启引导完成率 | 0（未实现） | ≥ 60%（可跳过） |
| 摘要查看率 | 0（无摘要） | ≥ 80% |
| 结论保存率 | 0（无结论） | ≥ 40% |
| 报告/证据包导出率 | 未知 | ≥ 30% |
| 未匹配热点可补知识 | 无 | 有 |
| 跨任务案例检索 | 无 | 有 |
| RCA 主界面入口 | 1 个一级 + 1 个 Tab | 0 个一级；设置页实验开关 |
| RCA 自动运行 | 导入即跑 | 不自动跑 |
| 前端红路线 E2E | 0 | 4 条 |
| 双开/数据丢失风险 | 高 | 单实例 + 自动备份 |

### 12.5 一句话总结

**LogAuditorGo 不需要更多"智能"，它需要更短的路径、更可信的证据、更完整的闭环。**  
把 RCA 放进设置页，把资源投入到原生导入、诊断摘要、案例结论、证据包与知识闭环，这个产品会从一个"工程师做的强大工具"，变成一个"一线工程师每天都愿意用的 Windows 桌面排障工作台"。

## 附录 B：实机走查观察

> 本次走查使用本地临时实例和仓库自带的 10 行 WLAN 示例日志；知识库为空，因此匹配率为 0。该场景用于说明"无知识库/首次使用"的体验，不代表有知识库时的完整效果。为遵守"仅修改方案文档"的要求，本文档不附带截图，仅保留观察摘要。

### B-1 工作台

观察：5 个一级视图、5 个主操作；右栏同时有"官方知识"和"RCA"两个 Tab；未匹配时右栏大面积空白；日志卡片只显示 Lv.N；注释行混排。

### B-2 仪表盘

观察：累计指标卡 + 空图表 + 快速开始；无最近任务、无待处理、无引导；空图表只显示很小的 "No data"。

### B-3 历史任务

观察：任务级"设备类型"列已不参与匹配但仍展示；状态英文 COMPLETED；操作列在 1920px 下换行；无搜索/筛选/分页。

### B-4 系统设置

观察：只有日志策略与日志文件；没有索引健康、存储、备份、版本、诊断、实验室功能；与 README 描述不一致。
