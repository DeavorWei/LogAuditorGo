## 1. 执行摘要

本次审计覆盖 `web/src` 下 **30 个 Vue 文件（7 视图 + 14 通用组件 + 8 工作台子组件 + App.vue）+ 1 个全局 CSS + index.html**，累计 **15,602 行**（其中 CSS 约 **5,150 行，占 33%**）。采用「全量人工审读 + 正则量化扫描 + 编译产物（dist）交叉验证」的三重方法。

### 总体结论

项目的视觉基线是统一的（Slate 中性色 + Sky 蓝点缀，符合现代 SaaS 审美），**底层骨架健康**：组件拆分合理（工作台三栏 + 8 个 workbench 子组件）、交互反馈完整（筛选胶囊、冲突确认、进度追踪、快捷键体系）、空态/错误态已有系统性治理（代码注释中可见 UI-01~UI-18 的持续改进痕迹）。

但样式层存在**系统性的"令牌缺失"问题**：全站没有设计令牌文件，颜色、字号、圆角、间距全部以硬编码魔数散落在 30 个文件中，导致：

| 维度 | 现状 | 理想 |
|---|---|---|
| 硬编码色值 | **829 处、约 95 种不同色值** | 单一令牌源，业务代码 0 硬编码 |
| 字号 | **18 种**（含 9px/10px/10.5px/11.5px 微字号） | 8 阶字阶表 |
| 圆角 | **11 种**（2/3/4/6/8/10/12/50%/9999px…） | 6 阶 |
| 间距 | **11 种基数**（2~24px）无使用规则 | 标尺 + 语义规则 |
| 内联样式 | **122 处** | 0（除动态计算值） |
| 可键盘操作的自定义交互元素 | **0 / 20 个**（0 个 tabindex、0 个 role） | 100% |
| 自定义焦点样式 | **0 处** | 全局 focus-visible 策略 |
| 媒体查询 | **1 处** | 完整响应式断点体系 |
| `prefers-reduced-motion` | **0 处** | 全局动效降级 |
| `!important` | **39 处** | ≤ 3 处（仅主题覆盖） |

### 四个 P0 级问题

1. **主色双轨制**：自绘组件用品牌天蓝 `#0284c7`（52 处），而 Element Plus 全套组件（按钮/标签/链接/分页/单选/复选框/表格焦点态）仍是默认宝蓝 `#409eff`（22 处），同屏并列呈现**两种蓝**，品牌感被直接击穿。
2. **严重度语义色 4 套并存且互相矛盾**：同一条 Lv.4 日志，在列表卡片是琥珀色条、在详情面板是橙色徽标、在时间线是橙红徽标、在空格预览是橙底白字——**同一数据四种颜色语言**，直接损害审计场景的快速判读。
3. **QuickTagModal 本地重复的标签色板与全局常量不一致**（12 色 vs 7 色，顺序与取值均不同），导致同一入口创建的标签颜色与其他入口不同。
4. **穿透语法三种拼写混用**（`:deep(`×10、`::deep(`×15、`::global(`×3），虽当前均可编译生效，但废弃拼写在工具链升级时存在失效风险。

### 重构策略（四层推进）

```
令牌化（tokens）→ 主题化（Element Plus 对齐）→ 组件化（共享样式抽取）→ 人性化（a11y/人体工程学）
```

预计 **10 个工作日**分 5 个阶段完成，每阶段独立可验证、可回滚，全程 `npm run build` + 截图回归护航。重构后硬编码色值从 829 处降至 **0**（lint 强制），重复 CSS 消除约 **600 行**，键盘可达性与对比度全部达到 WCAG 2.1 AA。

### 2.2 方法

1. **全量人工审读**：逐一阅读 30 个 SFC 的 template / script / style 三段，记录样式声明、交互模式、状态覆盖。
2. **正则量化扫描**：对 `*.vue` / `*.css` 统计色值、字号、圆角、间距、`!important`、内联样式、`@media`、`tabindex`、`role`、`:focus-visible`、`prefers-reduced-motion`、`::deep`/`:deep`/`::global` 语法分布。
3. **编译产物交叉验证**：对 `web/dist/assets/*.css` 反查，确认 `::deep()` / `:deep()` / `::global()` 三种穿透语法在本工程 Vue/Vite 版本下**均能正确编译生效**（排除"样式疑似失效"的误报），同时确认 Element Plus 默认主题色确实进入产物。
4. **设计系统视角评估**：以令牌完整性、语义一致性、组件复用度、WCAG 2.1 AA / 2.2、人体工程学（Fitts/Hick 定律应用）为标尺。

## 4. 详细审计发现

> 编号规则：`P{0/1/2}-{n}`；优先级 P0=正确性/品牌受损，P1=一致性/可维护性，P2=人性化/体验精修。
> 每条给出：位置证据 → 影响 → 建议。

### P0-1 主色双轨制：Element Plus 未做品牌主题化

- **证据**：`main.js:4` 全量引入 `element-plus/dist/index.css`；`main.js:27` `app.use(ElementPlus, { locale: zhCn })`，无任何主题变量覆盖。自绘组件主色为 `#0284c7`（Sky-700），而 `el-button type="primary"`、`el-tag type="primary"`、`el-link`、`el-pagination`、`el-radio-button`、`el-checkbox`、`el-switch`、表格聚焦态均为 EP 默认 `#409eff`。同一界面（如 Documents 表格行内的 `el-tag` 与自定义 `.doc-name-text`）蓝绿并置。
- **影响**：品牌识别被稀释；"可点击主操作"的颜色信号不唯一；后续换肤需逐组件返工。
- **建议**：新增 `styles/element-theme.css`，以 CSS 变量覆盖 EP 主色阶（方案见 5.3），主色统一为 `#0284c7` 及其 light/dark 衍生档。

### P0-2 严重度语义色 4 套并存且互相矛盾

- **证据**（同一 syslog severity 映射）：

| 组件 | Lv0-2 | Lv3-4 | Lv5-6 | Lv7+ | 形式 |

| `AuditLogCard.vue:156-170` | 条 `#ef4444` | 条 `#f59e0b` | 条 `#3b82f6`（**蓝**） | 条 `#94a3b8` | 左侧色条 |
| `LogDetailPanel.vue:515-518` | `#dc2626`/`#fee2e2` | `#ea580c`/`#ffedd5` | `#ca8a04`/`#fef9c3` | `#0284c7`/`#e0f2fe`（**蓝**） | 文字徽标 |
| `AuditLogDetailModal.vue:638-641` | `#991b1b`/`#fee2e2` | `#9a3412`/`#ffedd5` | `#854d0e`/`#fef9c3` | `#475569`/`#f1f5f9` | 文字徽标 |

- **影响**：同一日志在列表/详情/时间线/预览中颜色不一致；更严重的是 **Lv5-6（通知级）在卡片色条是蓝色、在徽标是黄色**，"蓝色=通知"与"蓝色=品牌/可操作"的心智冲突；色弱用户难以依赖颜色分层。
- **建议**：建立全局唯一严重度映射（5 态：crit/err/warn/info/comment × text/bg/border/bar 四件套），收敛到 `styles/severity.css` + `useSeverity()` composable，暗色场景用 `.sev-on-dark` 变体（方案见 5.4）。

### P0-3 QuickTagModal 标签色板与全局常量不一致

- **证据**：`QuickTagModal.vue:125-129` 本地重复声明 `PREDEFINE_TAG_COLORS`（12 色：`#409EFF,#67C23A,#E6A23C,#F56C6C,#909399,#0284c7,#10b981,#f97316,#8b5cf6,#ec4899,#14b8a6,#6366f1`），而 `constants/tagColors.js:4-12` 的全局常量为 7 色（`#F56C6C,#E6A23C,#67C23A,#409EFF,#909399,#795548,#9C27B0`）。AdvancedFilterDrawer、AuditLogDetailModal、DeviceManager（colorPresets 12 色，第三套）各自为政。
- **影响**：同一用户从空格快速打标创建的标签颜色，与从批量打标/标签管理创建的完全不同；设备标识色与标签色两套体系无法互相暗示。
- **建议**：删除本地副本，统一引用 `constants/tagColors.js`；设备色板 `DeviceManager.vue:335-339` 与之对齐或明确区隔（建议：标签色=语义色板，设备色=分类色板，分别导出并文档化）。

### P0-4 穿透语法三种拼写混用

- **证据**：`:deep(`×12（WorkbenchNavBar、QuickTagModal、ImportProgressModal 等）、`::deep(`×13（Dashboard:296、Settings:367、AuditFilterBar、LogDetailPanel 等）、`::global(`×3（AuditFilterBar:1130-1136、ImportProgressModal:669）。已通过 dist 产物验证**三种写法当前均可编译生效**（非功能性 bug），但 `::deep()`/`::global()` 属废弃拼写，Vite 升级存在行为变更风险。
- **建议**：全量替换为 `:deep()`；teleport 场景统一采用"非 scoped `<style>` 块 + 前缀类名"或 `:global()` 单一模式，并在规范中固化。

### P1-5 无设计令牌，业务代码直书魔数

- **证据**：829 处硬编码色值、122 处内联样式；`styles/import-dialog.css` 虽定义了 `--imp-*` 令牌（25 处引用），但**全部自引用**——组件中零消费，Documents.vue 等宁可重复书写 `#0284c7` 也不用 `var(--imp-primary)`。
- **影响**：换肤/暗色模式/对比度修复需全局查找替换；视觉漂移无法阻止（如 Dashboard 与 Settings 的统计卡已漂移：padding 18px vs 16px、数值字号 26px vs 22px、图标 36px vs 32px）。
- **建议**：建立 `styles/tokens.css` 为唯一色值/字阶/间距/圆角/阴影/动效/z-index 来源（5.1），并以 stylelint 强制（第 6 章）。

### P1-6 详情面板 CSS 大面积重复（LogDetailPanel ↔ AuditLogDetailModal ↔ LogKnowledgePanel）

- **证据**：三个文件重复定义约 **60 个同名类**：`.section-box`、`.box-title`、`.flex-between`、`.raw-code`、`.event-summary-box-wb`、`.param-grid-enhanced`、`.param-card`、`.p-key`、`.p-desc-badge`、`.p-val-box`、`.template-box`、`.template-rendered`、`.inst-param-injected`、`.inst-param-placeholder`、`.rca-alert`、`.log-detail-tags-bar`、`.detail-tag-pill`、`.kb-header-card`、`.kb-block`、`.kb-subtitle`、`.kb-text`、`.action-box`、`.cause-text`、`.comment-kb-card`、`.comment-item`、`.c-label`、`.c-val`、`.rca-guide`、`.sev-crit/err/warn/info` 等，且取值已出现漂移（如 `.action-box` 在 AuditLogDetailModal 是"灰底绿左边框"、在 KnowledgeCenter 抽屉是"绿底绿边"、在 MultiDeviceTimeline 抽屉是"蓝底蓝边"、在 LogKnowledgePanel 是"白底灰边"——**同一"处理步骤"语义四种配色**）。AuditLogDetailModal 单文件 606 行 CSS 为全站最大。
- **影响**：任何面板级视觉调整需改 3 处；漂移已实际发生。
- **建议**：抽取 `styles/panels.css`（知识库/详情面板共享骨架）+ `styles/severity.css`，预计消除 **~600 行**重复 CSS。

### P1-7 内联样式 122 处

- **证据**：`MultiDeviceTimeline`×13、`Documents`×12、`DeviceManager`×10、`AdvancedFilterDrawer`×8、`MultiDeviceReport`×7、`Settings`×6、`Tasks`×5、`Dashboard`×5…。典型：`Tasks.vue:17` `<span style="font-weight:600;color:#0284c7;cursor:pointer">`（可点击文字）、`Documents.vue:109` `<span style="font-weight:600;color:#0284c7">📖 {{row.lib_name}}</span>`、`MultiDeviceReport.vue:28-36` 统计卡边框色内联、`RcaCenter.vue`×14（大量 `<div style="display:flex;...">` 布局内联）。
- **影响**：无法被令牌/主题覆盖；无法响应式；无法被 lint 约束；审查成本高。
- **建议**：布局类内联上提为 class；颜色/字重类走令牌；仅保留真正的动态计算值（如设备色 `:style="{backgroundColor: d.color}"` 属合理动态绑定，保留）。

### P1-8 同一模式三种实现

配套 composable `composables/useSeverity.js`：

```js
import { computed, toValue } from 'vue'

/** severity → 等级 class 的全局唯一映射（支持 Ref、getter 函数与普通值） */
export function useSeverity(severitySource, moduleSource) {
  const level = computed(() => {
    const mod = toValue(moduleSource)
    if (mod === 'COMMENT') return 'comment'
    const sev = Number(toValue(severitySource))
    if (isNaN(sev)) return 'info'
    if (sev <= 2) return 'crit'
    if (sev <= 4) return 'err'
    if (sev <= 6) return 'warn' // 与附录 C 严格对齐：Lv.5(Notice) 与 Lv.6(Info) 统一归入 warn 提示级
    return 'info'
  })
  const tagClass = computed(() => `is-${level.value}`)
  const stripClass = computed(() => `sev-strip is-${level.value}`)
  return { level, tagClass, stripClass }
}
```

### 6.3 新增样式铁律（写入 `docs/前端样式规范.md`）

1. 色值/字号/圆角/阴影/动效/z-index 一律引用 `tokens.css`，禁止硬编码。
2. 禁止内联 `style=`（动态计算值除外，且需注释说明）。
3. 交互元素必须为 `button`/`a`，或具备 `tabindex` + `role` + 键盘处理；一律继承 focus-visible。
4. 穿透语法统一 `:deep()`；teleport 样式用非 scoped 块 + 前缀类名。
