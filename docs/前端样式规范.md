# LogAuditor 前端样式与 UI 工程规范指南 (Style Guide)

> 版本：v1.0.0  
> 生效日期：2026-10  
> 适用范围：`web/` 前端应用所有 Vue 组件、页面模板与样式表

---

## 1. 核心治理原则与「七大样式铁律」

所有新组件开发、存量页面重构以及日常维护均必须严格遵守以下七条样式铁律：

### 铁律 1：零硬编码色值（Zero Hardcoded Colors）
- **禁止**在组件模板或样式中直接编写十六进制（`#xxxxxx`）、RGB（`rgb(...)`）或原始 HSL 颜色值。
- **必须**使用设计令牌（`var(--token-name)`）。唯一的色值声明点必须收敛在 `tokens.css` 和 `element-theme.css`。
- **豁免项**：ECharts Canvas 渲染配置（运行于独立画布上下文，详见本规范第 4 节）以及用户自定义数据驱动色（如标签预设调色板常量 `tagColors.js`）。

### 铁律 2：严禁非必要内联样式（No Unnecessary Inline Styles）
- **禁止**为了图省事在 HTML 标签上滥用 `style="..."`（如 `style="margin-top: 10px; color: #xxx;"`）。
- **必须**在 `<style scoped>` 中声明语义化类名，通过 CSS 规则统一定义。
- **豁免项**：真正由运行时数据动态计算的属性（例如 `:style="{ backgroundColor: device.color }"`、动态进度条宽度或自适应高度）。

### 铁律 3：废弃穿透语法清零与作用域穿透规范
- **禁止**使用已经废弃或标准不推荐的穿透语法：`>>>`、`/deep/`。
- **必须**统一使用现代 Vue 3 标准选择器：`:deep(.target-class)`。
- **必须**遵循“精准穿透原则”：`:deep()` 必须限定在当前组件所作用的局部容器内（如 `.audit-detail-modal-dialog :deep(...)`），禁止在全局无前缀穿透。

### 铁律 4：WCAG 2.1 AA 级对比度与键盘可访问性（Accessibility）
- 文本正文与背景色的对比度必须达到 **4.5:1** 以上；大号文本（≥18px 或加粗 ≥14px）与核心界面指示物对比度必须达到 **3:1** 以上。
- 绝不能仅仅依靠“颜色”作为传递严重度、状态的唯一媒介，必须同时配合文字、图标或形状（如 `SeverityTag` 内置形状指引）。
- 所有可交互元素必须具备清晰的高对比度焦点环样式（`outline: 2px solid var(--brand-500)`），并在非鼠标操作时可通过键盘 `Tab` 键聚焦。

### 铁律 5：禁止使用 Emoji 充当界面功能图标
- **禁止**使用系统 Emoji（如 📌、⚠️、🔍、📊、🏷️ 等）作为功能按钮或状态指示。Emoji 在各操作系统（Windows、macOS、Linux、移动端）下字形差异极大、无法跟随字体颜色着色、且缺乏读屏软件无障碍无标签支持。
- **必须**统一使用 `@element-plus/icons-vue` SVG 矢量图标组件（如 `<FolderOpened />`、`<WarningFilled />`），并消费设计系统色彩令牌。

### 铁律 6：人体工程学标尺与触摸目标尺寸
- **最小字号基线**：全站文本字号不得小于 **11px**（`--fs-xs`）。严禁出现 8px、9px、10px、10.5px 等残缺字号。
- **可点击区域基线**：所有交互元素（折叠把手、标签胶囊、筛选药丸、操作图标按钮等）的可点击区域尺寸不得小于 **24px × 24px**。较小文字按钮需通过内边距（padding）扩张其可命中范围。

### 铁律 7：零负 Margin Hack 与消除 `!important` 滥用
- **禁止**使用负边距（Negative Margin，如 `margin-bottom: -18px`）去抵消父容器或表单项的默认间距。表单内边隙清除必须显式声明 `:deep(.el-form-item) { margin-bottom: 0; }`。
- **严禁**在日常业务样式中使用 `!important`。覆盖第三方组件（如 Element Plus）样式时，应通过拼接组件根类名（如 `.audit-detail-modal-dialog.el-dialog`）或提供定制上下文变量（如 `--el-menu-bg-color`）提升自然特异性。

## 2. 设计令牌（Design Tokens）体系与使用指南

所有设计系统变量均定义在 `web/src/styles/tokens.css`。编写样式时应首选语义令牌（Semantic Tokens），次选基础色标（Palette Tokens）。

### 2.1 品牌色与功能语义色令牌

| 令牌名称 | 典型用途 | 亮色模式基准值 |
| :--- | :--- | :--- |
| `--brand-600` | 品牌主色、主操作高亮、链接悬浮态 | `#0284c7` (Sky-600) |
| `--brand-500` | 主色悬浮、焦点环强调色 | `#0ea5e9` |
| `--brand-50` | 品牌浅底、选中行微高亮背景 | `#f0f9ff` |
| `--success-text` | 成功/正常/已恢复 文本 | `#15803d` (Green-700) |
| `--success-bg` | 成功状态浅底 | `#f0fdf4` |
| `--success-strong`| 成功强调色、图标 | `#16a34a` |
| `--warning-text` | 警告/异常 文本 | `#92400e` (Amber-800) |
| `--warning-bg` | 警告状态浅底 | `#fffbeb` |
| `--warning-strong`| 警告强调色、图标 | `#d97706` |
| `--danger-text`  | 严重/阻断/失败 文本 | `#991b1b` (Red-800) |
| `--danger-bg`   | 危险状态浅底 | `#fef2f2` |
| `--danger-strong` | 危险强调色、关键警示图标 | `#dc2626` |
| `--info-text`    | 提示/信息 文本 | `#075985` |
| `--info-bg`     | 提示状态浅底 | `#f0f9ff` |
| `--info-strong`  | 提示强调色、信息图标 | `#0284c7` |

### 2.2 文本与表面（Background & Text）语义令牌

```css
/* 文本阶梯 */
--text-primary: var(--gray-900);        /* 正文主标题、核心数值 */
--text-regular: var(--gray-700);        /* 通用正文、属性名 */
--text-secondary: var(--gray-500);      /* 次级说明、时间戳、元数据 */
--text-placeholder: var(--gray-400);    /* 输入框占位符 */

/* 背景与面板阶梯 */
--bg-surface: var(--gray-0);            /* 卡片、面板、对话框背景 */
--bg-subtle: var(--gray-50);            /* 斑马纹、工作台灰色衬底 */
--bg-active: var(--brand-50);           /* 列表选中行、激活项背景 */
--border-base: var(--gray-200);         /* 标准分割线、组件外边框 */
--border-light: var(--gray-100);        /* 细内部分割线 */
```

### 2.3 字号梯度（Font Size Scale）

严禁使用任意非标字号，严格遵守以下梯度阶梯：

| 令牌名称 | 像素大小 | 典型应用场景 |
| :--- | :--- | :--- |
| `--fs-xs` | **11px** | 最小辅助标签、时间戳角标、快捷键提示徽章 |
| `--fs-sm` | **12px** | 次级元数据、表格次级说明、状态药丸徽标 |
| `--fs-base` | **13px** | 紧凑模式正文、日志详情属性表格 |
| `--fs-md` | **14px** | 界面基准正文、输入框、表单文本、默认按钮 |
| `--fs-lg` | **16px** | 模块副标题、弹窗标题、重要统计数值标签 |
| `--fs-xl` | **18px** | 页面大标题、统计卡片核心数字 |
| `--fs-xxl` | **24px** | 仪表盘重点看板指标数值 |

### 2.4 圆角与阴影（Radius & Elevation）

- **圆角**：
  - 小零件/内嵌徽章：`--radius-sm` (4px)
  - 按钮/输入框/下拉项：`--radius-md` (6px)
  - 卡片/面板外框：`--radius-lg` (8px)
  - 浮层/模态弹窗：`--radius-xl` (12px)
  - 全圆胶囊/药丸：`--radius-full` (9999px)
- **阴影**：
  - 微浮动：`--shadow-sm`
  - 下拉菜单/快捷面板：`--shadow-md`
  - 模态弹框/顶层抽屉：`--shadow-lg`

### 2.5 工作台响应式布局令牌

工作台三栏布局宽度采用全局 CSS 变量分发，子组件通过变量自适应消费：

```css
:root {
  --wb-col-left: 28%;   /* 左栏日志流基准宽 */
  --wb-col-mid: 44%;    /* 中栏日志详情基准宽 */
  --wb-col-right: 28%;  /* 右栏知识图谱基准宽 */
}

/* 响应式断点控制 */
@media (max-width: 1600px) {
  :root {
    --wb-col-left: 32%;
    --wb-col-mid: 34%;
    --wb-col-right: 34%;
  }
}

@media (max-width: 1279px) {
  .workbench-body {
    flex-direction: column;
    --wb-col-left: 100%;
    --wb-col-mid: 100%;
    --wb-col-right: 100%;
  }
}
```

## 3. 严重度与根因标签色标基线

在展示网络故障日志严重度、RCA 根因传播链路节点时，必须严格使用统一设计的语义类与令牌：

### 3.1 日志严重度基线（Log Severity）

| 级别 (Level) | 语义色令牌 | 边栏色条 (Bar) | 形状无障碍标识 |
| :--- | :--- | :--- | :--- |
| `CRITICAL` (1-2) | `--sev-crit-bg` / `--sev-crit-text` | `--sev-crit-bar` (`#ef4444`) | 实心圆点 / 红色警报 |
| `ERROR` (3) | `--sev-err-bg` / `--sev-err-text` | `--sev-err-bar` (`#f97316`) | 三角告警 / 橙色告警 |
| `WARNING` (4) | `--sev-warn-bg` / `--sev-warn-text` | `--sev-warn-bar` (`#eab308`) | 菱形 / 黄色警告 |
| `INFO` (5-6) | `--sev-info-bg` / `--sev-info-text` | `--sev-info-bar` (`#94a3b8`) | 蓝色圆圈 / 常规信息 |
| `COMMENT` (#) | `--sev-comment-bg` / `--sev-comment-text` | `--sev-comment-bar` (`#64748b`)| 井号 / 注释说明 |

> **最佳实践**：业务代码中应直接使用 `<SeverityTag :level="row.severity" />` 组件，严禁在业务视图内拼接临时的 `el-tag` 颜色配置。

### 3.2 根因拓扑与排查指引基线（RCA Topo）

- **故障根因 (Root Cause)**：使用 `--impact-text` / `--impact-bg`（深红调底）或 `--sev-crit-bar`。
- **故障中间传播 (Intermediate)**：使用 `--warning-strong`（橙调）。
- **受累边缘 (Leaf/Impact)**：使用 `--gray-500`。
- **排查建议与处置动作 (Action)**：使用 `--action-text` / `--action-bg` / `--action-border`（绿色调底），表达正面修复与安全策略。

## 4. 推荐组件开发范式与最佳实践

### 4.1 语义化交互与无障碍焦点模式

#### 模式 A：单点动作按钮
若元素仅为一个触发动作（如快速复制、折叠、清空、药丸点选），使用 `<button type="button" class="... reset">`：

```html
<!-- 推荐 -->
<button
  type="button"
  class="action-pill reset"
  @click="handleClick"
>
  <el-icon><CopyDocument /></el-icon>
  <span>复制报文</span>
</button>
```

```css
/* base.css 中已提供 button.reset 基础重置 */
.action-pill {
  min-height: 24px;
  padding: 2px 8px;
  font-size: var(--fs-xs);
  border-radius: var(--radius-sm);
  cursor: pointer;
  display: inline-flex;
  align-items: center;
  gap: 4px;
}
.action-pill:focus-visible {
  outline: 2px solid var(--brand-500);
  outline-offset: 1px;
}
```

#### 模式 B：复合数据卡片
若列表项、日志条目本身包含复杂子元素，需整体响应点击与键盘操作：

```html
<!-- 推荐 -->
<div
  class="log-row-item"
  :class="{ 'is-selected': isSelected }"
  role="button"
  tabindex="0"
  @click="handleSelect(log)"
  @keydown.enter.space.prevent="handleSelect(log)"
>
  <div class="row-prefix">...</div>
  <div class="row-content">...</div>
</div>
```

```css
.log-row-item:focus-visible {
  outline: 2px solid var(--brand-500);
  outline-offset: -2px;
}
```

### 4.2 模态框与第三方组件定制特异性提升模式

覆盖 Element Plus 对话框、菜单或下拉面板样式时，严禁使用 `!important`，推荐以下两种方式：

#### 方案 1：结合自定义类与原生类提高自然特异性
```html
<el-dialog class="audit-detail-modal-dialog" ...>
```
```css
/* 自然特异性 (2个类名 > 1个类名)，无需 !important 即可优雅覆盖 */
.audit-detail-modal-dialog.el-dialog {
  border-radius: var(--radius-xl);
  background: var(--bg-surface);
}

.audit-detail-modal-dialog .el-dialog__header {
  padding: 12px 16px;
  border-bottom: 1px solid var(--border-base);
}
```

#### 方案 2：利用 Element Plus CSS 变量定制通道
```html
<el-menu class="nav-menu" ...>
```
```css
.nav-menu.el-menu--horizontal {
  --el-menu-bg-color: var(--gray-0);
  --el-menu-text-color: var(--text-regular);
  --el-menu-active-color: var(--brand-600);
  --el-menu-hover-bg-color: var(--bg-subtle);
  border-bottom: 1px solid var(--border-base);
}
```

### 4.3 表单紧凑排版治理模式

消除为了压缩表单垂直间距而设置负 margin 的不良习惯：

```css
/* 错误做法 (Hack) */
.compact-form {
  margin-bottom: -18px; /* 严禁出现负 margin */
}

/* 正确做法 (标准覆盖) */
.compact-form :deep(.el-form-item) {
  margin-bottom: 0;
}
```

### 4.4 ECharts 与 Canvas 色值规范

ECharts 无法直接解析外部 CSS 变量字符串作为颜色值：
- 如需在图表中使用系统色，在图表配置中统一采用系统令牌对应常量标尺，并在顶部进行注释说明。
- 严禁随意拼写未经校准的鲜艳颜色。

## 5. 样式检查清单（Checklist for Code Review & CI）

在每次代码合并或阶段交付前，请对照本清单自检：

- [ ] **Hex 色值清零**：运行 `git grep -n -E "#[0-9a-fA-F]{3,8}" web/src ":!web/src/styles/*"`，除已登记豁免项外无匹配。
- [ ] **内联样式审计**：无任何硬编码视觉样式的 `style="..."`，所有 `:style` 均为数据计算属性。
- [ ] **作用域穿透审计**：无 `>>>` 或 `/deep/` 废弃语法，所有穿透均使用 `:deep()`。
- [ ] **负 Margin 审计**：运行 `git grep -n -E "margin(-[a-z]+)?:\s*-[0-9]" web/src`，结果为 0。
- [ ] **!important 审计**：除 `base.css` 的媒体偏好减弱动画（`prefers-reduced-motion`）外，业务组件内 0 个 `!important`。
- [ ] **字号合规**：全站无 `< 11px` 残缺字号。
- [ ] **无障碍聚焦测试**：全键盘（按 `Tab` 键）能依次遍历工作台交互元素，且具有高可见度焦点轮廓环。
- [ ] **构建与测试**：`npm run build` 打包无 CSS 警告，`npm run test:unit` 全部通过。
