# Phase 4 战略选项决策评审

> 依据：《产品功能与体验优化分析及演进规划》v1.1 §8.2（Phase 4，Q2 以后）与 §8.7“本年度明确不做”
> 状态：决策评审（不实施）
> 结论：**本年度不进入开发**；每项仅在通过需求验证与 ROI 门槛后单独立项。

---

## 1. 背景

规划把 Phase 4 定义为“战略选项”，并列明本年度明确不做：实时 Syslog、LLM 助手、多厂商、深色模式。
该阶段不是排期内的交付，而是一个**决策门**：先证明需求真实、成本可承受、不破坏桌面单机定位，再决定是否启动。

本阶段交付物为决策记录与评估门槛，不产生代码、配置或半成品开关；
`features.browser_upload / lan_mode / masking` 仍保持“接口拒绝开启”的产品边界。

---

## 2. 逐项评审

### 2.1 实时 Syslog 接收

| 维度 | 结论 |
| :-- | :-- |
| 用户价值假设 | 值班场景可“边收边看”，减少导出文件再导入的步骤 |
| 成本 | 中~大：UDP/TCP 监听、落库背压、断线重连、端口冲突、防火墙提示、与离线任务模型融合 |
| 前置条件 | 明确“单机监听端口”的安全边界；任务模型从“文件导入”扩展为“流式任务” |
| 主要风险 | 与“离线、零外部依赖”定位冲突；长期运行的资源占用；日志乱序与时钟漂移 |
| 决策门槛 | ≥5 名目标用户明确表示每周使用；可接受仅监听本机回环；MVP 可在 3 周内交付 |
| 本期决定 | **不做**（规划明确本年度不做） |

### 2.2 LLM 诊断助手

| 维度 | 结论 |
| :-- | :-- |
| 用户价值假设 | 用自然语言总结日志、生成排查建议 |
| 成本 | 中~大：模型接入、离线模型体积/显存、Prompt 安全、幻觉与合规、证据引用 |
| 前置条件 | 客户允许本地模型；有可验证的准确率基准；明确“建议非官方结论” |
| 主要风险 | 幻觉导致误判；与“官方知识优先”的信任模型冲突；打包体积与硬件要求 |
| 决策门槛 | 在 50 条真实案例上，建议采纳率 ≥60% 且无严重误导；可完全离线运行；不改变现有证据链 |
| 本期决定 | **不做** |

### 2.3 多厂商（H3C/Cisco/Juniper）

| 维度 | 结论 |
| :-- | :-- |
| 用户价值假设 | 混合厂商网络可统一排障 |
| 成本 | 大：每厂商解析器、知识格式、匹配规则、测试语料与文档版权 |
| 前置条件 | 拿到合法语料与知识来源；确认目标客户占比；解析器可插拔架构 |
| 主要风险 | 稀释“华为官方知识”护城河；维护成本线性增长 |
| 决策门槛 | ≥30% 目标客户存在混合厂商且愿意付费/共建；单厂商 MVP ≤4 周 |
| 本期决定 | **不做** |

### 2.4 深色模式

| 维度 | 结论 |
| :-- | :-- |
| 用户价值假设 | 夜间/长时间使用舒适 |
| 成本 | 小~中：设计令牌双主题、组件适配、截图/报告样式一致性 |
| 前置条件 | 设计令牌已集中（现状满足）；ECharts/Element Plus 主题可控 |
| 主要风险 | 半成品主题造成对比度/可读性问题；报告与页面不一致 |
| 决策门槛 | 完成设计令牌评审；对比度达 WCAG AA；不影响打印/导出 |
| 本期决定 | **不做**（优先级低于知识闭环与稳定性） |

---

## 3. 统一评估流程（未来启用时）

1. **需求证据**：访谈/工单/使用数据达到门槛，不接受“我觉得有用”；
2. **ROI 估算**：开发 + 维护 + 支持成本 vs 可量化收益；
3. **架构影响**：是否破坏离线、单机、零上传、官方知识优先；
4. **最小验证**：2~4 周可回滚的 MVP，带成功指标；
5. **决策记录**：通过则进入下一阶段规划，不通过则记录原因与复评时间。

---

## 4. 本期结论

- Phase 4 四项战略选项**均不实施**，不新增代码/配置；
- 现有产品边界（无浏览器上传、无 LAN 多用户、无脱敏、无 RCA 演进）保持不变；
- 复评时间：下一个年度规划窗口，或出现满足上述门槛的明确需求时。
